## 1. 交付目标与阶段关系

在本机浏览器完成：上传一个小型系统的资料 → 自然语言指定分析目标 → 展示来源与补问 →
只读检索真实 Neo4j → DeepSeek 生成参考性分析 → 查看并导出候选 FMEA 报告。
中文 UI 和报告；约一周为可放宽的目标窗口，不是硬性截止或性能承诺。

本里程碑复用 MVP-1，并选取 MVP-2 检索、MVP-3 生成与最小 UI/报告能力。
不是把 MVP-2 至 MVP-5 全部宣布完成。原 MVP-2 草案保留为后续完整检索阶段的参考；
Demo 范围以内由本规格定义输入、检索与生成边界，范围以外仍遵守 AGENTS 与已接受 ADR。
运行结果始终是 Candidate FMEA，不构成人工审查批准或完整工程认证。

## 2. 首个案例与适用范围

首例使用项目自有的 `tests/fixtures/sysml/models/typed_inside_probe.sysml` 原样副本。
系统 `hydraulicPump`；首个目标 `motor`，其功能 `spin`。
该文件本次已由既有适配器解析，`load_status=ok`，0 diagnostics；详细 hash/范围见 D0 记录。
它是工程模型读取的教学夹具，不是真实航空产品或经过工程验证的液压系统设计。

根动作 `pumpSpin` 在 CSM 中存在，但当前 workflow 只分析组件功能；首例报告必须显示根动作未纳入分析。
不从类型名推断额定电压、转速、材料、数量、工作循环或标准符合性。
派生 BOM/设计说明逐项标注模型来源；未表达的数值留空。
可以提供独立的 `scenario.example.json`，但其中设定必须标为 SYNTHETIC_ASSUMPTION，
由 UI 展示为演示假设，不能冒充 SysML 原文或默默预填成已确认事实。

现有 Neo4j 和 SysML 案例独立。产品分析即使无适用历史知识也必须能演示参考性推理。
另设知识浏览用例，用已有图的真实名称验证来源检索；其命中不是泵—电机模型的工程对应。

## 3. 输入与交互契约

### 3.1 首版输入

- 一个 `.sysml` 必需；不支持仅文档自动重建系统模型。缺少时 UI 明确索取模型。
- 一个可选设计说明：UTF-8 `.md`/`.txt` 或可提取文本的 `.pdf`。
- 一个可选 BOM：UTF-8 `.csv` 或 `.xlsx` 的 `BOM` 工作表。
- 配套演示资料三类齐全；用户只提供 SysML 时，其余资料缺失必须在报告列出。
- BOM 固定列：`item_id,parent_id,name,quantity,unit,source_element_id`。
  `quantity` 可空；物料数量不从部件声明数量推导；formula 单元格拒绝，不执行宏/公式。
- 每文件最多 5 MiB；PDF 最多 20 页；BOM 最多 200 数据行；提取文本最多 30,000 字符。
  这些是 Demo 资源上限，不是工程容量指标。超限明确拒绝，不静默截断。
- 不支持扫描 PDF/OCR、CAD、DOCX、压缩包、旧 `.xls` 用户上传及 SysML 用户文件 imports。
  既有 `.xls` 知识来源核验属于受控离线研究，不复用旧 importer。

上传文件按生成 ID 存入当前会话目录，不把客户端文件名直接作为路径。
解析器按实际内容检查类型；输入错误、加密 PDF、无文本 PDF、无目标或 partial SysML 显式阻止分析。
用户文件和模型输出均是数据，不执行其中的命令、任意工具调用、链接或外部资源请求。

### 3.2 分析范围与补问

首版每次分析一个组件/功能对；UI 从 CSM 提供合法目标，默认首例 motor/spin。
自然语言用于选择目标、提问、补充工况和表达分析侧重点；模型提出的 target ID 必须属于当前 CSM。
姓名/显示名相似不能合并对象。用户给出的别名仅作为本次查询词，保留来源和未经验证状态。

首个必问项为工作状况：运行环境、运行阶段/工作循环、主要负载，可回答未知。
最多两轮集中补问；仍未知可选择继续参考性分析，保留假设和缺失项。
结构冲突、目标 ID 不存在、解析错误不能靠“按假设继续”绕过。
缺少 BOM/设计说明不强迫无限补问；UI 提示其缺失，允许按模型已知事实分析。

## 4. 来源、状态与报告契约

规范输出使用 `schema_version="demo-v1"`。该版本独立于包版本与模型服务版本。
每次会话携带文件 SHA-256、源文件名、来源定位、解析器/运行时版本及输入清单摘要。
模型的 `Model.hash` 继续仅表示 load-context fingerprint；不得改写成跨路径稳定身份。
引用采用会话内 ID 与内容 hash 组合；图 element ID 只用于本次检索定位，不作为永久知识主键。

字段级事实包含值、来源引用、知识状态和限制；生成候选统一为 CANDIDATE，
其中新增失效/起因/影响/措施等生成字段标为 INFERENCE。
精确引用的历史原文可以标为 RETRIEVED_KNOWLEDGE，但应用到当前对象的结论仍是推断。
引用 ID 必须存在于本次 evidence registry；不能允许模型创造工作簿行号、来源或 APPROVED 状态。
引用存在检查只证明定位有效，不证明该引用支持结论；UI 必须允许看到原文核对。

报告必须包含：

1. 候选报告标识、分析对象/功能/工况、范围、排除项和输入版本。
2. 系统事实摘要，以及模型、BOM、设计说明之间的关联和冲突。
3. 候选失效表：模式、起因、可选机理、局部/上一级/最终影响、已有控制、建议措施。
4. 各字段证据、推断/未知标记、适用性局限和建议验证方法。
5. 查询词、检索状态、图定位和无行级来源的限制；不得把图路径拼装成“原始 FMEA 行”。
6. 缺失信息、待确认问题、未覆盖的模型功能和错误/部分完成说明。
7. 风险状态固定 NOT_EVALUATED；S/O/D/AP 不生成，历史来源原值也不作为当前评分。

生成的“建议措施”不等于优化完成；七步状态中风险 NOT_EVALUATED、优化 SKIPPED。
报告允许记录建议，不宣布措施实施、效果确认或正式 Human Review 已完成。
导出 JSON（完整结构）+ 自包含 HTML（人可读报告）+ UTF-8 BOM CSV（候选表）。
HTML 转义所有输入，无脚本/外链；CSV 防止 `= + - @` 等公式前缀被表格应用执行。
HTML 可通过浏览器打印；DOCX/独立 PDF 排版不在首版验收范围。
成功报告必须自包含完整输入清单、CSM快照和证据，脱离当前会话仍可导出。
生成失败使用单独的 FAILED 诊断报告（JSON/HTML）保存输入摘要与安全错误，
不创建空的成功候选报告或候选 CSV。

## 5. 真实知识检索切片

### 5.1 固定查询与检索结果

新增提供方无关 `SourceKnowledgeRepository.search(query) -> RetrievalResult`；
旧 `FailureKnowledgeRepository.find_failure_modes` 仅保留 MVP-0/1 兼容路径，不作为 Demo 的来源知识接口。
原草案期望的长期端口迁移继续后置，不在此以改名制造“全部 MVP-2 完成”。

查询词来自当前对象/功能及有记录的用户输入；LLM 可提出查询词但不能生成 Cypher。
最多 5 个词、每词最多 80 字符，NFKC/去首尾空白/casefold 用于排序，不以归一化文本作为身份。
固定只读模板对 name 作精确或包含匹配，保留原词和匹配原因；最多返回 20 个模式。
排序为精确名称优先，再按原始名称和本次定位 ID 排序。是否截断必须显式记录。

模板只沿已知标签与关系查找关注要素、功能、下层部件及模式；
模式到起因/影响/控制的边各自独立返回，禁止对分支笛卡尔积重建 FMEA 行。
共享模式涉及多个关注要素时保留所有已查询关联的来源上下文；不可归属的模式级边标为上下文未知。
固定模板、参数化输入和代码级无写入口共同实施只读边界。
`routing_="r"` 本身不是授权控制；不运行用户 Cypher、APOC 或导入/迁移语句。

### 5.2 不混淆检索和适用性

`retrieval_status`：HITS / NO_MATCH / ERROR。
`applicability`：UNKNOWN / REJECTED / SOURCE_CONTEXT_ONLY，分别表示未确认适用、明确排除、仅确认来源上下文。
Demo 不自动生成“已批准跨案例适用”的结果。
NO_MATCH 只表示该次有界查询无结果，UI 不声称整个知识库绝无适用知识。
词法 HITS 也不等于已找到可直接应用的知识；相关但无法确认时显示“相关知识，适用性待确认”。
明确不适用的结果不进入生成上下文，只保留排除理由；全部被排除时报告“无可用参考知识”，
但保留原始 HITS 检索审计，而非篡改数据库查询结果。
连接/超时/认证错误必须显示 ERROR；用户仍可明确选择仅按已知资料推理，报告显示检索失败。

## 6. DeepSeek 生成

提供方实现位于适配器中，使用现有 `LLMClient.generate(prompt: str) -> str` 契约。
应用层分别解析 intake JSON 和 analysis JSON，禁止 Neo4j/HTTP/UI 类型进入领域。
默认官方端点 `https://api.deepseek.com/chat/completions`，模型 `deepseek-v4-pro`。
采用非流式 JSON Output：`response_format={"type":"json_object"}`、`thinking={"type":"disabled"}`，
prompt 明确要求 JSON 并包含 schema 示例；应用侧仍用严格 Pydantic 校验。
这是 [官方接口](https://api-docs.deepseek.com/api/create-chat-completion/)支持的组合，
真实账号能力尚须 live smoke 验证。官方提示 JSON Output 可能返回空内容，不能把空内容当作零失效结果。
[JSON Output 说明](https://api-docs.deepseek.com/guides/json_mode/)。

模型只接收本次选定演示资料的必要文本、限定目标、允许引用清单和明确区分的检索上下文。
资料中缺少的产品属性必须保持未知；推理须说明工程假设与建议验证方法，不要求展示内部思维链。
缺少历史知识时允许 INFERENCE；已有控制的 FACT 值必须有来源，模型不得创造为既有措施。

HTTP 连接超时 10 秒、读取等阶段超时 60 秒（不是整个请求/会话总截止）；响应最大 1 MiB。
同一次逻辑请求最多一次重试，仅 429/502/503/504 且全局请求预算允许时重试。
认证失败不重试；空内容、截断、非法 JSON、schema/引用校验失败显式失败，不无限修复。
单会话最多 6 次 HTTP 请求（含重试），单次输出上限 4096 tokens。
界面 rerun 不自动调用模型；每次分析由请求 ID 防止同一会话重复提交。
费用不作未经核验的固定金额承诺；报告记录服务返回的 token usage（可缺失）、请求次数与模型名。
模型名为可变服务别名，记录调用日期与响应中的模型标识，不声称永久固定权重版本。

## 7. UI 与最小知识积累

单用户本机 Streamlit UI，绑定 127.0.0.1；不部署公网、不引入账户/多租户。
页面分为上传与输入摘要、分析对话、候选表/证据详情、报告下载四区。
显示真实/模拟模式、连接状态、待补问项、分析范围与当前报告状态；前端不展示密钥或内部堆栈。
上传后切换文件会使旧分析失效；结果与文件 hash/请求 ID 绑定。
补问与回答在当前会话保存，重启后可重新运行；持久审查流程、多人批准、知识库自动更新不实现。

用户可导出候选报告和修订备注；它是可复用工件的起点，不自动成为已批准知识。
原 Neo4j 保持只读。向其写回、候选晋升、模型训练和自我学习均不属于 Demo V1 完成条件。

## 9. 验收场景

| ID | 必须证明的行为 | 验证方式 |
|---|---|---|
| A01 | 样例原文件 hash 固定，派生资料没有编造参数 | 生成器确定性测试、源字段比对 |
| A02 | 单文件 SysML → CSM → motor/spin，根动作明确未覆盖 | 真实本地解析+既有契约 |
| A03 | BOM/PDF/TXT 内容有定位；错误/冲突不静默合并 | 文件适配器与 intake 测试 |
| A04 | 自然语言选择合法目标、补问、未知可继续 | 固定 LLM 响应+会话测试 |
| A05 | Neo4j 真查询可定位知识，并区分无结果与故障 | fake driver 契约+已配置本机只读 smoke |
| A06 | 词法命中不升级跨案例适用，无依据图路径不变原表行 | 共享模式/多起因多影响回归 |
| A07 | 无可用历史知识仍可生成标记为 INFERENCE 的候选 | mock+DeepSeek 演示输入 live smoke |
| A08 | 伪造来源/目标/评分/批准状态、空/截断输出被拒绝 | 提供方和领域校验负例 |
| A09 | HTML/JSON/CSV 保留证据、状态和缺失项 | 序列化往返与导出检查 |
| A10 | UI 一次提交只分析一次，错误可见，报告可下载 | AppTest+本机浏览器完整操作 |
| A11 | MVP-0/1 回归不退化、领域无技术依赖污染 | pytest/ruff/mypy、benchmark |
| A12 | 未声称概率校准、已批准报告或知识自动写回 | UI/报告文案及独立复审 |

自动化参考样例：SysML 结构与来源来自固定预期快照；检索测试按原始来源记录组织；
人工构造“不存在标识”仅测状态，不充当工程不适用 gold。
生成文本测试验证契约与边界，不以模型自生成答案作工程标准答案；保留少量人工抽查接口。
未有人工抽查时可记录“技术演示通过，工程质量未验收”，不得宣称已验证完整性/准确率。
无 API/数据库配置时 LOCAL mock 测试可通过，但真实 Demo 外部接入验收必须标为待验证。

## 10. 实施出口

D1 案例/资料 → D2 输入/来源契约 → D3 只读检索 → D4 模型适配 → D5 工作流 →
D6 报告/UI → D7 验证与演示。D3 检索失败必须可独立定位；不能用 LLM 输出掩盖它。
每阶段运行相关测试并独立复审，阶段收尾记录位于 `docs/records/DEMO_V1/`；
同一 Stage 切换会话使用现有模板，不增加另一个“当前状态”文件。
本次 D0 仅完成规格/计划及准备证据；真实能力与后续完成时间以各阶段执行记录为准。
