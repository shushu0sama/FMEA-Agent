仓库许可证为 MIT。[作者仓库](https://github.com/lukasbahr/kg-rag-fmea)、
[许可证](https://github.com/lukasbahr/kg-rag-fmea/blob/0800a2597575849bf9807bb09536c33435f83d3f/LICENSE)。

### 2.2 IBM Research FMEA Builder — 专家分步监督的生成原型

该研究把生成任务按文档结构分解，用相关历史示例构造提示，并让专家确认、拒绝或补充结构化结果。
论文实验集中在设备边界和失效位置，采用专有 FMEA 数据；作者说明数据不能公开用于复现。
本次未确认可直接复用的公开代码或数据集。
[论文 v1，2024-11-07](https://arxiv.org/html/2411.05054v1)。

**本项目判断：R — Reference only。** 可借鉴字段级监督与示例适用性确认。
本项目已有 SysML 工程事实，设备结构优先取自工程模型；LLM 不能静默重建或覆盖它。
该研究不提供本项目的七步法完整实现或风险规则授权。

## 3. 对后续讨论的建议

以下是结合本仓库约束的判断，不是外部作者对本项目的结论，也尚未成为实施计划。

1. **先确认一组来源能否对应。** 从已有 SysML 选择一个可解析的对象和功能；
   从现有 Neo4j 选择可能相关的知识。记录直接依据、差异和不可确认项。
2. **先评测检索，再评测生成。** 用人工核对的命中、无命中、歧义、冲突和不适用样例，
   验证来源定位、实体匹配和上下文完整性。人工参考答案不由待测检索器生成。
3. **缺失行级信息不能通过图遍历凭空恢复。** 旧图共享名称节点形成的间接路径，
   不自动证明某个起因、控制和功能曾处于同一原始 FMEA 行。
4. **结构事实与历史知识保持独立。** 当前 CSM 的局部 ID 不是永久知识身份；
   来源已批准也不自动批准它在当前设计上的应用。
5. **MVP-3 再讨论生成。** 模型基于已确认的工程上下文及带来源的知识生成候选，
   同时保留拒绝、未知和人工修改能力。无需提前引入多智能体、向量库或知识写回。

## 4. 后续需要确认的信息

- 第一组 SysML 文件及版本、希望分析的模型根/组件/功能。
- Neo4j 只读访问方式或可脱敏导出的子集；凭证通过环境变量或本机配置传入，不写入文档和聊天。
- 两组数据的产品关系；若只是类比来源，应明确为适用性待审查。
- 来源 Excel/CSV 是否仍可获得，以及谁能核对少量参考匹配。

这些信息用于后续讨论；本次 MVP-1 发布复核不以获取它们为前提。
